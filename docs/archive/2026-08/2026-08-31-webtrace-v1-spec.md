# WebTrace V1 网站使用统计规格

- 日期：2026-08-31
- 状态：已完成（2026-09-01，实施与经批准的验收口径已收口）
- 目标平台：Chrome Manifest V3 扩展

## 1. 背景与目标

WebTrace V1 用于回答一个清晰的个人统计问题：我每天打开某个网站多少次、实际看了多久、分别在什么时间打开。

首版需要支持用户手动配置多个网站，所有数据只保存在本机。用户点击扩展图标后进入分析页，查看某个网站最近 7 天的打开次数、有效使用时长和逐次打开明细。

## 2. 首版范围

### 2.1 包含

- 手动添加和停用多个统计网站。
- 记录每次有效打开的时间。
- 记录每次打开对应的有效观看时长。
- 按网站展示最近 7 天的每日打开次数和每日有效使用时长。
- 展示最近 7 天合计以及选中日期的逐次访问明细。
- 在本地长期保存访问记录，直到用户主动删除或卸载扩展。
- 点击扩展图标直接打开分析页。

### 2.2 不包含

- 网页悬浮时长组件。
- 使用提醒、网站限制或强制关闭。
- 登录、云同步或跨设备同步。
- 数据导入、导出或分享。
- 自定义时间范围、历史周翻页或跨网站汇总。

## 3. 核心定义

### 3.1 统计网站

用户添加的一个可注册主域名及其全部子域名。例如，`zhihu.com` 同时匹配 `www.zhihu.com` 和 `zhuanlan.zhihu.com`，但不匹配 `fakezhihu.com`。

用户可以输入主域名、无协议域名或任意 HTTP/HTTPS 页面 URL。系统会移除协议、路径、端口和开头的 `www.`，并通过随扩展打包的离线公共后缀规则归一化为可注册主域名。归一化后的主域名是网站的唯一标识，同一主域名不能重复添加。

### 3.2 有效打开

一次顶层标签页导航从非当前统计网站进入当前统计网站，记为一次有效打开。导航方式不影响结果：地址栏输入、书签、历史记录、站外链接、前进或后退都可以产生有效打开。

以下规则消除重复计数：

| 场景 | 是否增加打开次数 | 处理方式 |
| --- | --- | --- |
| 非目标网站进入目标网站 | 是 | 新建访问记录 |
| 空白新标签页独立打开目标网站 | 是 | 新建访问记录 |
| 目标网站刷新 | 否 | 延续当前访问记录 |
| 目标网站内部跳转，包括不同子域名 | 否 | 延续当前访问记录 |
| 从目标网站打开同站内容的新标签页 | 否 | 新标签页继承原访问记录 |
| 切换到已经打开的目标网站标签页 | 否 | 恢复原访问记录的计时 |
| 离开目标网站后再次进入 | 是 | 结束旧记录并新建记录 |
| 从统计网站 A 进入统计网站 B | B 增加一次 | 结束 A 的关联状态，为 B 新建记录 |

在后台标签页中发生的有效打开也会增加打开次数，但在该标签页真正成为当前可见页面前，有效观看时长为 0。

### 3.3 访问记录

一次有效打开对应一条访问记录。记录至少包含：

```text
Visit {
  id
  siteId
  openedAt
  endedAt | null
  activeIntervals[]
  lastConfirmedAt
  lastActivityAt
}

ActiveInterval {
  startedAt
  endedAt | null
}
```

`openedAt` 决定打开次数归属的本地日期。`activeIntervals` 是该次打开期间真正观看网站的时间段，是使用时长的唯一计算依据。总时长和每日时长均从访问记录推导，不另设可能失真的日汇总作为数据源。

同站内容在新标签页中打开时，新标签页关联原 `Visit`，而不是新建一次打开。只要该访问记录仍有关联的目标网站标签页，它就保持进行中；所有关联标签页均关闭或离开该网站时，记录结束。

### 3.4 有效观看时长

只有以下条件同时满足时才累计时长：

1. 标签页当前 URL 属于该访问记录的网站。
2. 标签页是其 Chrome 窗口的当前活动标签页。
3. Chrome 窗口处于前台且未最小化。
4. 页面处于可见状态。
5. 设备未锁屏。

切换标签页、切换到其他应用、最小化 Chrome 或锁屏都会立即暂停；重新满足条件后，在同一访问记录内开启新的有效时间段。用户长时间阅读或播放视频时，即使没有键盘和鼠标输入，也继续计时。普通“无操作”状态不能被当作离开。

一个时刻最多只能有一个有效时间段正在累计，因此多个打开的目标网站标签页不会造成重复计时。有效时间段跨越午夜时，聚合器按本机日历边界拆分时长到相邻两天。

## 4. 用户界面

### 4.1 分析页入口

扩展不再使用网页内悬浮组件。用户点击浏览器工具栏中的扩展图标后，打开或聚焦 WebTrace 分析页。

### 4.2 最近 7 天趋势页

分析页一次展示一个统计网站，默认时间范围是“今天加前 6 天”。首版不提供日期范围切换。

页面包含：

- 网站切换列表。
- 最近 7 天总打开次数。
- 最近 7 天总有效使用时长。
- 按日排列的打开次数趋势。
- 按日排列的有效使用时长趋势。
- 当前选中日期的访问明细。

两个趋势使用对齐的日期轴，但分别展示次数和时长，避免把不同单位放在同一个双轴图中。默认选中今天；用户点击某个日期或柱形后，下方明细切换到该日。

明细按打开时间从新到旧排列，只列出 `openedAt` 属于所选日期的记录，展示：打开时间、结束时间、该次访问的完整有效时长。仍在进行的记录显示“进行中”。没有数据的日期显示 0 和空状态，不隐藏该日期。

趋势图中的每日时长严格按有效时间段发生的日期拆分；明细中的时长则回答“这一次打开总共看了多久”。因此，一次访问跨越午夜时，它只计入打开当天的明细和打开次数，但它的有效时长会分别进入两天的趋势统计。这一差异由明细标题中的说明明确表达。

### 4.3 网站管理

分析页提供网站管理入口。用户可以：

- 输入网站名称和域名或页面 URL。
- 添加归一化后未重复的网站。
- 停止或恢复某个网站的后续统计。
- 删除某个网站的全部历史记录。

停止统计只影响未来采集，历史记录继续可见。删除历史是独立操作，需要明确说明影响并进行二次确认。新增网站时，不追溯统计当前已经打开的页面；下一次有效打开才开始形成记录。

网站切换列表同时保留已启用和已停用的网站，并明确显示状态，从而保证停用后仍能查看历史。删除历史不删除网站配置；如果网站仍为启用状态，删除后产生的新访问会继续被记录。

## 5. 系统结构

### 5.1 组件职责

#### 后台服务工作线程

- 监听顶层导航、标签页创建与关闭、活动标签页变化、窗口焦点变化和设备锁屏状态。
- 对 URL 进行网站匹配并执行打开次数状态机。
- 管理标签页与访问记录的关联关系。
- 开始、暂停和结束有效时间段。
- 以事务方式持久化访问记录并响应分析页查询。

#### 静默内容脚本

- 不创建任何可见 UI。
- 报告页面可见性变化。
- 在满足计时条件时发送低频存活确认，用于限制浏览器异常退出造成的误差。

#### 分析页

- 管理统计网站配置。
- 查询指定网站最近 7 天所需的访问记录。
- 在页面内完成按天聚合和展示。
- 不直接修改正在进行的访问状态。

#### 领域逻辑模块

域名归一化、URL 匹配、打开状态机、有效时间段计算和 7 天聚合应保持为不依赖 Chrome UI 的独立逻辑，以便自动测试。

### 5.2 本地存储

- 网站配置和轻量运行状态保存在扩展本地存储中。
- 访问记录保存在扩展自己的 IndexedDB 中，并按 `siteId + openedAt` 和 `siteId + lastActivityAt` 建立查询索引。
- 标签页到访问记录的临时映射保存在会跨服务工作线程重启存续的会话存储中。
- 所有存储均属于扩展本机空间，不发送网络请求。

访问记录是统计结果的唯一事实来源。分析页打开时读取所选网站中“在最近 7 天打开”或“在最近 7 天发生过有效观看”的记录并取并集，现场计算图表和明细。这样，早于本周打开但本周仍在使用、或跨越周边界后才结束的记录不会漏计。

### 5.3 扩展权限

首版只申请实现已确认功能所需的权限：本地存储、顶层导航与标签页状态、窗口焦点、锁屏状态，以及动态统计任意 HTTP/HTTPS 网站所需的主机访问权限。宽泛的主机访问仅用于用户已经配置的网站匹配与页面可见性汇报，未配置网站不生成访问记录。

## 6. 事件与恢复流程

### 6.1 新建访问

1. 后台收到顶层导航事件。
2. 归一化目标 URL，并匹配已启用的统计网站。
3. 根据当前标签页旧网站、创建来源和关联访问判断是否属于新打开。
4. 新打开则立即写入一条 `openedAt` 已确定的记录；同站延续则复用现有记录。
5. 若页面同时满足有效观看条件，则开始首个有效时间段。

### 6.2 暂停与恢复

任何影响有效观看条件的事件都会触发一次状态重算。条件由满足变为不满足时关闭当前时间段；由不满足变为满足时创建新时间段。重复事件必须是幂等的，不能产生重叠时间段或重复打开记录。

### 6.3 正常结束

标签页关闭、导航到非当前网站、网站被停用或浏览器正常关闭时，结束相应关联。某条访问记录不再有任何关联标签页后，设置 `endedAt` 并关闭尚未结束的有效时间段。

### 6.4 异常恢复

- 服务工作线程重启：从会话状态恢复标签页关联，从持久记录恢复进行中的时间段，不增加打开次数。
- 浏览器异常退出：未结束记录只统计到最后一次存活确认，恢复时在该时间点结束旧记录，不能把浏览器关闭后的时间计入。
- 浏览器重新启动并实际恢复目标网站页面：这是一次新的页面打开，创建新记录；旧记录不复用。
- 存储写入失败：本次变更不更新内存中的已提交状态，进行有限重试并记录错误，避免界面显示已保存但实际丢失。
- 用户输入错误：无效地址、非 HTTP/HTTPS 地址和重复主域名在保存前被拒绝，并在分析页显示可操作的错误信息。

异常退出造成的时长误差上限由存活确认间隔控制；首版目标是不超过 5 秒，且只允许少计，不能把未观看时间多计进去。

## 7. 数据与隐私

- 不上传 URL、访问记录或统计结果。
- 访问记录默认长期保留，不自动过期。
- 用户可以删除单个网站的历史数据。
- 卸载扩展后由 Chrome 清除扩展本地数据。
- 首版只接受 HTTP/HTTPS 网站，不统计浏览器内部页面和扩展页面。

## 8. 测试策略

### 8.1 自动测试

- URL 归一化、公共后缀处理、精确主域名和子域名匹配。
- 新进入、刷新、站内导航、离开后返回、跨统计网站、同站新标签页继承等打开状态。
- 标签页、窗口、页面可见性和锁屏变化下的开始、暂停、恢复与结束。
- 无输入的长时间观看继续计时。
- 多标签页场景下任一时刻不重复累计。
- 跨午夜时间段拆分。
- 最近 7 天每日次数、每日时长、合计和访问明细聚合。
- 服务工作线程重启和异常退出恢复。
- 网站重复添加、停用、恢复和删除历史。

### 8.2 Chrome 手动验收

至少用知乎完成以下真实浏览器流程：

1. 从站外页面打开知乎，确认次数增加且打开时间正确。
2. 刷新、站内跳转并从知乎打开知乎新标签页，确认次数不增加。
3. 切换到其他标签页或应用并等待，再返回，确认离开期间不计时。
4. 在知乎停留阅读但不操作，确认持续计时。
5. 关闭或离开知乎后重新打开，确认产生第二条记录。
6. 检查最近 7 天图表与合计符合有效时间段的按日拆分，且当天明细与当天打开的访问记录一致。
7. 重启扩展服务工作线程和浏览器，确认不重复计数且不累计离线时间。

## 9. 验收条件

满足以下条件即认为 V1 完成：

- 用户能配置至少一个网站并开始本地统计。
- 每次符合定义的打开恰好生成一条记录。
- 不符合定义的刷新、站内跳转和同站新标签页不会增加次数。
- 只有用户真正观看目标网站时才累计时长。
- 分析页能准确展示每个网站最近 7 天的打开次数、有效时长和打开时间明细。
- 所有自动测试通过，且第 8.2 节的真实 Chrome 场景全部验收通过。
- 页面中不存在悬浮计时组件，也不存在网络同步行为。
