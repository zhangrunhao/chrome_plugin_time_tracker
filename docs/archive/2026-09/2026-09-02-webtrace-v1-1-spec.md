# WebTrace V1.1 分析页与持续统计规格

- 日期：2026-09-02
- 状态：已完成
- 目标版本：`1.1.0`
- 目标平台：Chrome Manifest V3 扩展

## 1. 结论

WebTrace V1.1 在不改变 V1 计时、访问记录和本地隐私契约的前提下，改进分析页的当天概览和近期趋势图，并移除网站暂停与恢复能力。

报表范围由最近 7 天改为固定展示最近 14 个本地日，不提供日期选择或超过 14 天的查看入口。更早的数据继续按现有保留策略存储。网站添加后持续统计；已有停用网站在升级时恢复统计。

本次继续使用当前的全 HTTP/HTTPS 主机权限、静态内容脚本和 `webNavigation` 导航机制。Notion 原 V1.1 第 5 条“按网站单独申请访问权限”已由用户于 2026-09-02 明确撤销，不属于本 Change。

## 2. 背景与目标

V1 已支持多网站本地统计、最近 7 天趋势和逐次访问明细。V1.1 需要让分析页更适合观察近期变化，并减少网站管理中的状态分支。

本次目标是：

- 打开分析页后立即看见所选网站今天的打开次数和有效使用时长。
- 用两张上下排列、占满内容区宽度的折线图展示每日趋势。
- 固定查看最近 14 个本地日，不显示日期选择控件。
- 网站添加后持续统计，不再提供停止或恢复按钮。
- 保持 V1 已验证的打开、计时、恢复、本地存储和删除历史语义。

### 3.2 2026-09-02 用户确认

- 分析页固定展示今天及此前 13 天，不提供日期选择；超过 14 天的数据先不展示，但不删除历史记录。

## 4. 范围

### 4.1 包含

- 顶部概览改为所选网站的当天打开次数和当天有效使用时长。
- 两个趋势模块改为上下排列的通栏布局。
- “每日打开次数”和“每日有效使用时长”均改为折线图。
- 默认展示今天及此前 13 天，共 14 个本地日。
- 不显示日期选择控件，趋势固定展示今天及此前 13 天。
- 移除停止统计、恢复统计及其用户界面和消息命令。
- 已添加网站持续统计；已有停用网站升级后恢复统计。
- 保留网站切换、网站添加、历史删除和逐次访问明细。
- 将扩展版本更新为 `1.1.0`。

### 4.2 不包含

- 按网站申请可选主机权限，或缩小当前 HTTP/HTTPS 主机访问范围。
- 移除或替换 `webNavigation`。
- 登录、账号同步、跨设备同步、导入、导出或分享。
- 使用提醒、休息提醒、网站限制或强制关闭。
- 跨网站汇总，以及按周、月或时段分布的独立报表。
- Chrome Web Store 的隐私政策、品牌素材、商店文案、发布 ZIP 和提交流程。
- 修改访问记录结构、IndexedDB 版本或数据保留期限。
- 自定义日期范围，以及查看最近 14 天以前的历史趋势或明细。

## 5. 保持不变的 V1 契约

除本规格明确修改的界面和网站启用行为外，下列 V1 契约继续有效：

- 一次顶层导航从非目标网站进入目标网站产生一次有效打开。
- 刷新、站内跳转、跨子域名跳转和同站新标签页继承不增加打开次数。
- 只有目标标签页活动、窗口前台且未最小化、页面可见、设备未锁屏时才累计有效时长。
- 打开次数按 `openedAt` 的本地日期归属。
- 有效时长按本地午夜拆分到实际发生日期。
- 访问明细归属打开日，并显示该次访问的完整有效时长。
- 访问记录只保存在本机，不发送网络请求，不保存完整 URL、路径、查询参数或网页标题。
- 新增网站不追溯已经打开的页面；离开后再次进入才创建新访问。
- 删除历史只删除目标网站的访问记录，保留网站配置。

## 6. 分析页设计

### 6.1 页面结构

分析页从上到下包含：

1. 页面标题和“管理网站”入口。
2. 错误提示区域。
3. “今日概览”模块。
4. “每日打开次数”通栏折线图。
5. “每日有效使用时长”通栏折线图。
6. 当前选中日期的访问明细。

网站切换列表继续位于左侧。小屏布局继续按现有响应式规则收拢，但两个趋势模块在所有宽度下都保持上下排列，不恢复双列布局。

### 6.2 今日概览

“最近 7 天合计”改名为“今日概览”，包含：

- 今日打开次数。
- 今日有效使用时长，格式继续为 `HH:MM:SS`。

今日以用户本机日历为准。概览始终展示今天，不随明细选中日期变化。切换网站时，概览切换为新网站的今日数据。

### 6.3 固定近期范围

分析页不显示起始日期、终止日期或“应用”按钮，也不提供其他日期快捷预设。

- 每次读取报表时，终止日期为本机今天，起始日期为今天前第 13 个本地日，首尾均包含。
- 范围按本地日历日推进，不使用固定 24 小时毫秒数，以免夏令时切换造成日期偏移。
- 没有记录的日期仍显示零值。
- 切换网站时继续使用同一个滚动 14 日范围。
- 分析页跨过本地午夜后，第一次自动刷新将范围前移一天；已选日期仍在新范围内时予以保留，否则选择新的今天。
- 最近 14 天以前的访问和活动区间继续保存在 IndexedDB，分析页暂不查询或展示这些日期。

### 6.4 折线图

两张图使用同一日期轴和范围，但各自使用独立纵轴比例，不使用双轴混合图。

每张图必须满足：

- 每个日期对应一个数据点，相邻数据点用折线连接。
- 打开次数使用非负整数；有效时长使用非负毫秒值并以可读时长展示。
- 零值日期保留在日期轴上，并绘制在基线上。
- 全部日期均为零时仍展示完整日期轴和基线，不隐藏模块。
- 当前选中日期在两张图中使用一致的选中样式。
- 点击任一图的数据点都会选中该日期并刷新下方访问明细。
- 每个数据点可通过键盘聚焦和触发，并提供包含完整日期和值的无障碍名称。
- 鼠标悬停、键盘聚焦和选中状态均能看见对应日期和值。
- 14 个日期均保留可访问的数据点和标签。

折线图使用随扩展提供的 SVG 和 DOM 实现。不得加载远程图表代码、远程字体或运行时第三方资源。

### 6.5 访问明细

明细继续按选中日期的 `openedAt` 归属，并按打开时间从新到旧排列。每条记录继续展示打开时间、结束时间、完整有效时长和进行中状态。

默认选中今天。点击折线图数据点后，两张图和明细使用同一个 `selectedDateKey`。

## 7. 网站管理设计

### 7.1 持续统计

网站管理对话框移除停止与恢复按钮。侧栏和管理列表不再区分“统计中”与“已停用”，并明确提示“网站添加后将持续统计”。

新网站继续以 `enabled: true` 保存。为降低 V1.1 的迁移和状态机风险，存储模型暂时保留 `enabled` 字段，但它在 V1.1 中是始终为 `true` 的内部兼容字段，不再是用户可修改的产品状态。

### 7.2 已有停用网站迁移

后台初始化时检查现有网站配置：

- `enabled: false` 的记录改为 `enabled: true` 并持久化。
- 网站 ID、名称、域名、创建时间和历史访问记录保持不变。
- 迁移通过现有网站同步流程更新运行状态，但不得追溯当前已经打开的页面。
- 下一次离开后重新进入该网站时，才按 V1 打开语义创建新访问。
- 迁移必须幂等；重复启动不会重复写入或创建访问记录。

### 7.3 删除历史

删除历史继续需要二次确认。确认文案必须明确说明：

- 现有访问记录会永久删除且无法撤销。
- 网站配置会保留。
- 删除后网站仍会持续统计，新访问会再次产生记录。

## 8. 报表与数据流

### 8.1 滚动日期窗口

现有固定 7 天窗口改为滚动 14 天。底层窗口生成器继续接受 `startDateKey` 和 `endDateKey`，但分析页只用今天及此前 13 天调用它。窗口生成器按本地日历逐日构造日期项，并返回：

- 起始日本地午夜时间戳。
- 终止日下一日的本地午夜时间戳，作为右开边界。
- 按日期升序排列且包含零值日的日期列表。

聚合器继续从 `Visit` 和 `ActiveInterval` 推导结果，不新增日汇总缓存。

### 8.2 报表结果

报表至少返回：

```text
Report {
  range: { startDateKey, endDateKey }
  todaySummary: { openCount, activeMs }
  days[]: { dateKey, openCount, activeMs }
  selectedDateKey
  details[]
}
```

原最近 7 天 `totals` 不再作为顶部概览的数据来源。实现可以保留内部范围合计，但 V1.1 界面不展示它。

### 8.3 查询策略

所选范围内的访问记录继续通过 `siteId + openedAt` 与 `siteId + lastActivityAt` 两个索引取并集，确保以下记录不会遗漏：

- 在范围内打开的访问。
- 在范围前打开、但在范围内仍有活动时间的访问。

分析页的滚动 14 日范围始终包含今天，因此今日概览复用同一批访问记录。底层数据源保留独立今日窗口能力，但 V1.1 界面不提供触发历史自定义范围的入口。

查询结果按访问 ID 去重。IndexedDB schema、索引和数据库版本保持不变。

## 9. 控制器与错误行为

控制器每次加载报表时根据本机今天计算滚动 14 日范围，并使用网站、该范围和选中日期查询。控制器和视图不再保存已应用范围、日期输入或日期错误状态。

稳定错误行为包括：

| 场景 | 行为 |
| --- | --- |
| 报表读取失败 | 保留稳定的页面错误提示，并允许用户重试 |
| 网站为空 | 保持现有无网站空状态和添加入口 |

网站添加、历史删除和自动刷新继续使用现有串行与错误封装机制。

## 10. 组件影响

预计受影响的职责边界如下，具体文件拆分由实施计划确定：

- `manifest.json`：版本更新为 `1.1.0`；权限和内容脚本范围保持不变。
- 报表领域逻辑：固定 7 天窗口泛化为本地日窗口，并增加今日概览；分析页固定传入滚动 14 日范围。
- 分析数据源：接受内部日期范围并构造范围与今日数据。
- 分析控制器：每次刷新计算滚动 14 日范围并管理选中日期。
- 分析视图与样式：移除日期控件，使用通栏折线图替换柱形图。
- 网站服务与协议：移除启用状态修改命令，增加旧停用配置的幂等迁移。
- 自动测试与 Chrome 验收：更新 7 天合计、柱形图和停用/恢复相关断言。

## 11. 权限、隐私与已接受风险

V1.1 不新增权限，也不缩小现有权限：

- `permissions` 继续为 `idle`、`storage`、`unlimitedStorage` 和 `webNavigation`。
- `host_permissions` 继续覆盖 `http://*/*` 与 `https://*/*`。
- 静态 `content_scripts.matches` 继续覆盖全部 HTTP/HTTPS 页面。

代码仍只为用户配置的网站生成访问记录，未配置网站不保存访问数据。运行时代码继续不得调用 `fetch`、`XMLHttpRequest`、`WebSocket` 或 `EventSource`，也不得加载远程可执行代码。

宽泛主机权限和 `webNavigation` 可能增加 Chrome Web Store 的权限说明与审核风险。该风险已由用户于 2026-09-02 明确接受；只有实际审核未通过时，才另建 Change 设计按网站授权或导航机制调整。本规格不得预先实现该方案。

## 12. 自动测试

实施后至少覆盖：

- 滚动 14 日窗口包含正确的首尾日期和零值日期。
- 底层日期窗口继续覆盖严格解析、跨月、跨年、闰日和夏令时日历推进。
- 跨月、跨年、闰日以及存在夏令时变化的本地日范围按日历日计算。
- 不存在的日历日期被严格拒绝，不能由日期解析器自动修正后接受。
- 打开次数继续按 `openedAt` 归属，有效时长继续跨午夜拆分。
- 切换网站和自动刷新始终查询当前滚动 14 日范围。
- 跨过本地午夜时，滚动范围前移且今日概览切换到新日期。
- 点击任一折线图数据点会同步选中两张图并更新明细。
- 零值折线、全零范围和 14 天图表均能渲染。
- 数据点具备键盘交互和完整无障碍名称。
- 网站管理不再暴露停止或恢复操作，协议不再接受对应命令。
- 已有 `enabled: false` 网站只迁移一次，保留历史且不回填当前页面。
- 删除历史后网站配置保持启用，并能记录后续新访问。
- manifest 版本为 `1.1.0`，权限和 HTTP/HTTPS 内容脚本范围与 V1 相同。

所有既有打开语义、计时、恢复、存储和分析页复用测试必须继续通过；因产品契约变化而更新的测试不得削弱这些行为。

## 13. Chrome 手动验收

重新加载未打包扩展后，至少验证：

1. 初次打开分析页默认显示最近 14 天，今日概览与实际数据一致。
2. 两张折线图上下排列并占满内容区宽度，在桌面和窄窗口均可使用。
3. 页面没有日期输入、应用按钮或超过最近 14 天的查看入口。
4. 点击和键盘触发任一图的数据点，另一张图的选中态和明细同步变化。
5. 网站管理中不存在停止或恢复按钮；新增网站后，下一次有效打开开始记录。
6. 删除网站历史后，配置仍存在，后续重新进入该网站会产生新记录。
7. 刷新、站内跳转、同站新标签页、离站后返回、切换标签页或应用等 V1 核心行为没有回归。
8. 扩展管理页显示的权限范围与 V1 一致，没有新增权限。

手动结果必须记录验证日期、Chrome 版本和覆盖场景。无法执行的场景必须明确标为未验证，不得用自动测试冒充手工通过。

## 14. 验收条件

满足以下条件才认为 V1.1 实现完成：

- 顶部准确展示所选网站今天的打开次数和有效使用时长。
- 两张通栏折线图准确展示同一个滚动 14 日范围。
- 页面没有日期选择或超过最近 14 天的查看入口，更早数据仍按既有策略保留。
- 折线图的数据点可由鼠标和键盘选择，并同步驱动访问明细。
- 网站管理不再提供停止或恢复，所有已有配置最终处于持续统计状态。
- V1 的打开、计时、恢复、本地存储、历史删除和隐私契约没有回归。
- manifest 版本为 `1.1.0`，现有权限范围保持不变。
- 与风险相称的自动测试、语法检查和真实 Chrome 验收已执行并记录结果。
- `docs/current` 已根据最终实现更新，本 spec 与实施计划已按仓库流程归档。

## 15. 后续但非本次工作

- Chrome Web Store 隐私政策、素材、商店资料、发布包和审核提交。
- 只有审核实际因权限或隐私问题未通过时，才设计按网站授权与更小权限方案。
- 登录、同步、提醒、限制、导入导出、日期范围、超过 14 天的历史查看、周/月报表和时段分布继续留待未来版本。
