# WebTrace 商店发布准备规格

## 当前结论

本 Change 为 WebTrace 首次提交 Chrome Web Store 准备可公开核验的产品页面、隐私披露、品牌图标、商店图片、可复制的商店字段、待上传扩展包和提交手册。WebTrace 继续保持本地优先：扩展不会把网站配置、访问记录或有效时长发送给开发者或第三方。

本 Change 与 `zhangrh.shop` 仓库中的同名 Change 配套实施。两个仓库都直接在 `main` 分支工作，但分别验证、提交和推送。

## 背景与依据

WebTrace 会处理用户配置的网站域名、打开时间和有效观看时长，因此即使数据只保存在本机，也属于 Chrome Web Store 要求披露的浏览活动数据。

截至 2026-09-03 核验的官方要求包括：

- 处理用户数据的扩展必须提供准确、最新且可从 Developer Dashboard 访问的隐私政策；
- 数据采集、用途和共享必须显著披露，数据只能服务于已披露的单一用途；
- 2026-08-01 起，所有数据采集均需要显著披露，且在采集前取得明确、知情的同意；
- 商店至少需要 128×128 图标、一张 1280×800 或 640×400 截图，以及一张 440×280 宣传图；
- 截图应展示真实产品体验，宣传图应以品牌表达为主。

官方依据：

- [Chrome Web Store Program Policies](https://developer.chrome.com/docs/webstore/program-policies/policies)
- [2026 Chrome Web Store policy updates](https://developer.chrome.com/blog/cws-policy-updates-2026)
- [Fill out the privacy fields](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy)
- [Supplying Images](https://developer.chrome.com/docs/webstore/images)
- [Publish in the Chrome Web Store](https://developer.chrome.com/docs/webstore/publish)

## 目标

1. 在开始记录某个网站前，以显著文本说明处理的数据、用途、本地保存、不共享和删除方式，并要求用户作出明确确认。
2. 让扩展图标、商店图标、宣传图和官网页面使用一致的 WebTrace 品牌语言。
3. 用纯合成数据生成真实扩展界面的商店截图，不包含真实用户数据。
4. 提供可直接复制到 Chrome Web Store Developer Dashboard 的中文发布资料和逐步提交清单。
5. 生成只包含运行必需文件的待上传 ZIP，并验证包内清单。
6. 在公开 WebTrace 官网上线后记录准确 URL，并把最终状态同步到现有 Notion 项目页面。

## 非目标

- 本 Change 不代替用户在 Chrome Web Store Developer Dashboard 中创建条目或点击“提交审核”。
- 不新增远程服务、账号、同步、广告、遥测、崩溃上报或产品分析。
- 不新增、扩大或改为可选权限；现有权限取舍保持不变。
- 不改变打开次数、有效时长、日期归属、历史查询或网站排序的业务语义。
- 不新增网站配置删除功能；“删除历史”仍保留网站配置并继续统计。
- 不在 zhangrh.shop Hub 中新增 WebTrace 作品卡；官网项目可独立发布，Hub 收录留给后续独立决定。

## 扩展内显著披露与确认

### 触发位置

披露放在分析页“管理网站”对话框的新增网站表单内，并位于提交按钮之前。新安装且没有配置网站时，WebTrace 不会保存访问记录；用户只有完成确认并提交网站后，才会为该域名及其子域名生成记录。

### 披露内容

界面需用简体中文清楚说明：

- 记录范围：用户填写的网站名称和可注册主域名、进入该网站的打开时间、结束时间及有效观看区间和时长；
- 有效时长条件：目标标签页处于活动状态、Chrome 窗口在前台且未最小化、页面可见、设备未锁屏；
- 用途：只用于在 WebTrace 分析页展示打开次数、最近 14 天趋势和逐次访问明细；
- 存储：全部保存在当前 Chrome 配置文件的扩展本地存储和 IndexedDB；
- 不处理：不保存完整 URL、路径、查询参数、页面标题、网页内容、输入内容或 Cookie；
- 不共享：扩展不上传这些数据，不出售、不用于广告，也不允许开发者或第三方读取；
- 保留和删除：记录默认长期保留，可按网站永久删除历史；卸载扩展会移除扩展本地数据。

披露区提供指向 `https://zhangrh.shop/webtrace/privacy` 的隐私政策链接。该链接只在用户主动点击时打开网页，不是扩展数据传输或远程代码。

### 明确同意

- 表单提供未默认选中的确认框，标签表达“我已了解并同意 WebTrace 为提供统计功能，仅在本机记录上述数据”。
- 未勾选时不能提交新增网站；浏览器原生表单校验应把焦点带到确认框。
- 每次成功新增网站后，文本输入和确认框一并重置。
- 已有网站的统计与现有数据不改变；本次是首次商店发布准备，不设计存量商店用户迁移。

### 可访问性与失败行为

- 确认框必须有可点击的完整文本标签，并可通过键盘操作。
- 隐私链接需有明确名称，不能只显示裸 URL。
- 新增网站失败时保留用户已填内容和确认状态，展示现有稳定错误消息；成功后才重置。
- 披露不会隐藏在折叠区域、悬浮提示或隐私政策单独页面中。

## 品牌与图片资产

### 视觉方向

品牌沿用产品界面的森林绿、暖白和深色文字。新图标以“时间轨迹”为核心：清晰的路径或趋势线、有限数量的节点和时间含义，正面视角、无文字、缩小后仍可辨识，不使用 Chrome 或其他第三方品牌元素。

### 运行图标

扩展仓库提供并在 manifest 中准确引用：

- `images/icon_16.png`
- `images/icon_32.png`
- `images/icon_48.png`
- `images/icon_128.png`

所有文件必须是对应像素尺寸的 PNG。128×128 图标遵循商店建议，在四周保留约 16px 透明边距；其他尺寸从同一母版生成并逐尺寸检查。现有未再使用的 64px 图标从运行清单移除。

### 商店图片

发布素材保存在 `store-assets/`：

- `screenshots/01-dashboard-1280x800.png`：真实分析页，展示网站列表、今日概览和趋势；
- `screenshots/02-add-site-1280x800.png`：真实管理网站对话框，展示显著披露和确认；
- `promo/small-promo-440x280.png`：品牌主导、少文字或无文字、满版且缩小后清楚；
- 可保留高分辨率品牌母版，供官网和未来素材复用。

截图在隔离的临时 Chrome 配置中加载当前扩展，用明确标注的合成网站和合成访问记录生成。不得使用本机现有 Chrome 配置、真实浏览记录、真实 Cookie 或真实扩展数据库。截图保持直角、满版、准确 1280×800，不添加会误导功能的装饰性 UI。

### 生成与验收

- 使用 ImageGen 生成品牌视觉候选或宣传图基础视觉；精确尺寸、透明边距和小尺寸清晰度由本地确定性处理完成。
- 图标和宣传图在浅色与深色背景上检查。
- 用图像元数据验证所有像素尺寸和 PNG/JPEG 格式。
- 逐张人工检查无个人数据、无虚构功能、无第三方商标误用和无裁切问题。

## 商店发布文档

新增 `docs/current/store-publishing.md`，在 Change 完成时作为当前发布手册和字段事实来源，控制在 300 行内。至少包含：

- 当前版本、待上传 ZIP 路径和生成方式；
- 商店标题、摘要和详细描述；
- 分类 `Productivity`、主要语言 `简体中文`、免费、公开发布建议；
- 单一用途说明；
- `idle`、`storage`、`unlimitedStorage`、`webNavigation`、HTTP/HTTPS 主机访问的逐项理由；
- Remote code 选择“No”；
- 数据披露建议：至少披露 Web history / browsing activity；若控制台把活动标签页观看时长单列为 User activity，则同时勾选并使用文档给出的说明；不勾选 Website content，因为扩展不读取或保存页面内容；
- Limited Use 各项认证及与公开隐私政策一致的说明；
- 主页、支持页、隐私政策 URL；
- 无账号、无付费、无测试凭据时的测试说明；
- 账号准备、ZIP 上传、Store Listing、Privacy、Distribution、Test instructions、提交审核和延迟发布的顺序；
- 发布前与审核通过后的核对清单；
- 官方文档链接和最后核验日期。

文档不得声称商店条目、审核、发布或线上商店链接已经存在，除非当次已实际核验。

## 打包

待上传 ZIP 放在 Git 忽略的发布输出目录或其他明确的本地构建输出位置，不把临时浏览器配置写入仓库。ZIP 根目录直接包含 `manifest.json`，并仅包含扩展运行需要的 HTML、CSS、JavaScript、`src/`、`vendor/` 和 `images/` 文件。

包内不得包含 `.git`、`node_modules`、测试、项目文档、商店宣传素材、临时截图数据或密钥。打包后解压到临时目录并重新运行 manifest JSON、入口 JavaScript、必需文件和远程代码检查。

## 官网与跨仓库契约

`zhangrh.shop` 仓库新增独立的 `webtrace` 前端项目并发布以下 URL：

- `https://zhangrh.shop/webtrace/`
- `https://zhangrh.shop/webtrace/support`
- `https://zhangrh.shop/webtrace/privacy`

官网中的数据范围、保留、删除和不共享表述必须与本规格及当前代码一致。扩展发布文档引用这些稳定 URL；在公网发布和验证成功前只标记为预期 URL。

## Notion 更新

两个仓库实现、验证、提交、推送和官网发布完成后：

1. 在已连接的 Notion 工作区搜索现有 WebTrace 项目或状态页面；
2. 读取页面结构后更新最匹配且明确属于 WebTrace 的现有页面；
3. 记录完成日期、代码 revision、公开 URL、生成的素材、验证结果和仍需用户手工执行的 Developer Dashboard 步骤；
4. 不把“材料已准备”写成“商店已提交”或“已通过审核”；
5. 若找不到唯一匹配页面，不猜测写入目标，并把该项报告为需要用户提供页面链接。

## 验收标准

### 扩展

- 未确认披露不能新增网站；确认后能新增，成功后表单和确认框重置。
- 既有统计、删除历史、排序和报表行为通过回归测试。
- manifest 精确引用 16/32/48/128 图标，不增加权限或远程代码。
- `npm test`、全部 JavaScript 语法检查、manifest JSON 检查和 `git diff --check` 通过。
- 在 Chrome 重新加载未打包扩展，验证披露、键盘确认、新增网站和隐私链接；记录浏览器版本、日期和场景。

### 素材与包

- 四个运行图标和所有商店图片尺寸、格式正确，视觉一致且不含真实用户数据。
- 至少两张截图来自当前真实扩展界面，使用隔离合成数据。
- 待上传 ZIP 根目录包含有效 manifest，运行文件完整且不含开发和私密文件。

### 官网与文档

- 三个 WebTrace 路由在桌面和 390px 宽视口可用，无横向溢出、控制台错误或失效内部链接。
- `zhangrh.shop` 完整检查通过，独立 `webtrace` 生产构建成功。
- 官网发布后，三个公网 URL 及其引用资源返回成功响应。
- `docs/current/store-publishing.md` 包含全部可复制字段、链接和提交步骤，且与代码和隐私政策一致。
- Notion 状态准确区分“已准备”“已部署”和“尚未提交商店”。
